# 건설중인자산 감가상각개시시점 손익영향 시뮬레이터

삼성전자·SK하이닉스 실제 사업보고서/감사보고서(DART)에서 추출한 데이터를 바탕으로,
핵심감사사항(KAM)으로 지적된 "건설중인자산 → 유형자산 대체(가동개시) 시점 판단"이
몇 개월 앞당겨지거나 늦춰졌을 때 손익에 미치는 영향을 계산하는 프로그램입니다.

## 폴더 구조

```
program/
  data/
    kam_facts.csv                     # 회사·연도별 KAM 대상 금액, 내용연수 가정, 근사 여부
    depreciation_split.csv            # 감가상각비의 매출원가/판관비/개발비 배분 비율
    cip_dataset.csv                   # 건설중인자산 잔액·감가상각비·자본화차입원가 원자료
    capitalized_borrowing_cost.csv    # 회사·연도·기준별 자본화된 차입원가·이자율
    goodwill_impairment_samsung.csv   # 삼성전자 보고부문(CGU)별 영업권 손상차손 (FY2023~2025)
    goodwill_impairment_skhynix.csv   # SK하이닉스 CGU(Solidigm 포함)별 영업권 현황
    board_resolutions_skhynix.csv     # SK하이닉스 신규 Fab 등 시설투자 이사회결의 내역
    total_assets.csv                  # 회사·연도·기준별 자산총계 (중요성 근사 계산용)
    audit_procedures.csv              # 회사·연도별 KAM 원문의 실제 감사절차(원문 발췌) + 원문 확인 여부
  cip_timing_simulator.py    # 핵심 계산 로직 (라이브러리)
  run_scenarios.py           # 전체 KAM 사례에 대해 시나리오 실행 + CSV/차트 출력
  dart_fetcher.py            # DART Open API로 재무제표를 자동 조회해 수기입력값과 대사(reconcile)
  output/
    scenario_summary.csv               # 시점조정 시나리오별 손익 영향 전체 표
    scenario_comparison.png            # 회사·연도별 비교 차트
    capitalization_scope_summary.csv   # 자본화 차입원가 자본화 vs 즉시비용화 비교
    multi_year_comparison.csv          # 연차별 누적 손익 영향 (0으로 수렴하는지 확인)
    materiality_summary.csv            # 대상금액의 자산총계 대비 비중 (중요성 근사)
```

## 실행 방법

```bash
cd program
python3 run_scenarios.py
```

`output/` 폴더에 `scenario_summary.csv`와 `scenario_comparison.png`가 생성됩니다.

개별 사례를 직접 다뤄보고 싶다면:

```python
from cip_timing_simulator import load_case_facts, run_scenario, run_scenario_set

facts = load_case_facts("skhynix", 2025, "consolidated")
result = run_scenario(facts, shift_months=3)   # 3개월 앞당긴 경우
print(result.delta_net_income)                 # 당기순이익 영향 (백만원)

# 여러 시나리오를 한 번에
for r in run_scenario_set(facts, shift_range_months=[-6, -3, 0, 3, 6]):
    print(r.shift_months, r.delta_net_income)
```

자본화 원가범위(자본화된 차입원가) 시나리오:

```python
from cip_timing_simulator import load_case_facts, load_capitalized_borrowing_cost, run_capitalization_scope_scenario

facts = load_case_facts("skhynix", 2025, "consolidated")
cap_cost = load_capitalized_borrowing_cost("skhynix", 2025, "consolidated")
r = run_capitalization_scope_scenario(facts, cap_cost)
print(r.delta_net_income)   # 차입원가를 자본화하지 않고 즉시 비용화했다면 당해년도 순이익이 얼마나 줄었을지
```

## 이 프로그램이 계산하는 것 / 계산하지 않는 것

계산하는 것: "만약 감사인이 문제 삼은 그 판단(가동가능 시점)이 실제보다 N개월
빨랐거나 늦었다면, 그 해 감가상각비·영업이익·당기순이익이 얼마나 달라졌을까"를
정액법 가정 하에 근사적으로 계산합니다.

계산하지 않는 것: 실제로 그 판단이 틀렸다는 뜻은 아닙니다. 감사인은 감사절차를
통해 회사의 판단이 적절하다는 결론(적정의견)을 내렸습니다. 이 시뮬레이션은
"판단 하나가 재무제표에 미치는 영향의 크기"를 체감하기 위한 학습 도구이지,
실제 판단의 오류를 지적하는 것이 아닙니다.

## 핵심 가정 (README 상단 docstring에 상세 설명, `cip_timing_simulator.py` 참고)

- 기준 시나리오: 연중 평균 7월 1일(6개월) 가동개시 가정
- 대상 금액: SK하이닉스는 KAM 원문에 명시된 실제 금액, 삼성전자는 KAM에 정확한
  금액이 공시되지 않아 재무제표 주석의 기계장치 취득액(건설중인자산 대체분 포함)
  으로 근사 — `kam_facts.csv`의 `population_source` 컬럼에 명시
- 내용연수: 주석 공시 대표추정내용연수 사용 (기본값 5년, 조정 가능)
- 법인세 실효세율: 기본 22% (조정 가능)

## 자본화 원가범위 시나리오 (`output/capitalization_scope_summary.csv`)

감가상각 "개시시점" 판단과는 별개로, 애초에 취득원가에 무엇을 자본화할지도
경영진 판단 영역입니다. 여기서는 자본화된 차입원가(이자비용)를 (a) 실제처럼
자본화해 내용연수에 걸쳐 감가상각하는 경우와 (b) 자본화하지 않고 발생 즉시
이자비용으로 전액 비용화하는 경우를 비교합니다.

| 사례 | 자본화된 차입원가(백만원) | 비자본화 시 당기순이익 영향 |
|---|---|---|
| SK하이닉스 FY2023(연결) | 136,622 | 약 -959억원 |
| SK하이닉스 FY2025(연결) | 249,760 | 약 -1,753억원 |
| 삼성전자 FY2024(연결) | 515,824 | 약 -3,621억원 |
| 삼성전자 FY2025(연결) | 557,852 | 약 -3,916억원 |

자본화(현재 실제 회계처리)는 같은 비용을 5년에 걸쳐 조금씩만 당기손익에
반영하는 반면, 비자본화는 전액을 당해년도에 즉시 비용화합니다 — "개시시점"
뿐 아니라 "자본화 범위" 판단 역시 당기 이익 규모를 좌우하는 별도의 회계적
레버라는 것을 보여줍니다. 시운전비용 등 이자비용 외 항목은 공시 자료에서
확인되지 않아 이번 시나리오는 자본화된 차입원가로 한정했습니다.

## 다년도 누적 모델 (`output/multi_year_comparison.csv`)

당해년도 1년치 영향만 보면 "가동시점을 늦출수록 유리하다"는 착시가 생길 수 있습니다.
하지만 총 상각액(population_at_risk)은 시점을 언제로 잡든 동일하므로, KAM 해당연도부터
자산이 완전히 상각되는 해(내용연수+1년차, 상각월수가 정확히 나눠떨어지면 내용연수년차)까지
누적으로 보면 Δ당기순이익은 결국 **0으로 수렴**합니다.

예를 들어 SK하이닉스 FY2023(연결) 사례를 6개월 앞당긴 경우:

| 연차 | Δ당기순이익 | 누적 |
|---|---|---|
| 1년차(FY2023) | -3,854억원 | -3,854억원 |
| 2~5년차 | 0 | -3,854억원 |
| 6년차 | +3,854억원 | **0** |

즉 "개시시점" 판단은 이익을 만들어내는 게 아니라 여러 해에 걸쳐 이익을 이동(재배치)시킬
뿐이라는 걸 보여줍니다 — 다만 당장 감사받는 그 해의 숫자만 보면 그 사실이 가려집니다.

이 판단 하나가 왜 핵심감사사항으로 지정될 만큼 유의적으로 취급되는지를 뒷받침합니다.

## 감사절차 ↔ 정량적 손익영향 매핑 (KAM 원문 대조, `data/audit_procedures.csv`)

지금까지의 시뮬레이션은 "이 판단이 틀렸다면 얼마나 손익에 영향을 주는가"라는 정량적
임팩트를 계산합니다. 그런데 실제 감사인은 이 임팩트를 근거로 *구체적으로 어떤 절차*를
선택했을까요? DART 감사보고서 원문에서 "핵심감사사항이 감사에서 다루어진 방법" 단락을
직접 추출하여, 시뮬레이터의 수치 결과와 나란히 놓아 봤습니다.

**원문 검증 방법**: `raw_filings/` 폴더의 파일명은 실제 회사·연도와 일치하지 않는
경우가 많습니다(예: "sk2026.txt"라는 이름이지만 내용은 삼성전자 감사보고서). 따라서
파일명이 아니라 본문에 등장하는 금액(예: 기계장치 52,704,853백만원, 당기 대체분
4,940,500백만원)이 `kam_facts.csv`의 수치와 정확히 일치하는지로 회사·연도를 확인했습니다.

### 원문이 확인된 사례

| 사례 | KAM 결정 이유 (원문 요약) | 감사에서 다루어진 방법 (원문 그대로, 발췌) |
|---|---|---|
| SK하이닉스 FY2023(연결) | 유형자산 52.7조원 중 기계장치 31.5조원, 당기 중 4,940,500백만원 사용가능 판단 후 감가상각 개시 | ①정책·프로세스 이해 ②내부통제 평가(건설중인자산 대체 포함 상각개시 결정, 장기 미대체 사유 파악) ③당기 대체분 표본추출 - 근거문서 사용개시일과 상각개시일 일치 검토 ④장기 미대체분 표본추출 - 예상 상각개시시점 질문·문서검토 |
| SK하이닉스 FY2023(별도) | 유형자산 39.0조원 중 기계장치 23.3조원, 당기 중 4,438,544백만원 | (연결과 동일 구조, 회사 단독 기준) |
| 삼성전자 FY2024(연결) | DS부문 반도체 공장 건설 중, 사용가능시점에 감가상각 개시 (정확한 금액은 KAM에 미공시) | ①정책·프로세스·내부통제 이해 ②승인 내부통제 평가 ③장기 미대체 CIP 파악·모니터링 내부통제 평가 ④표본추출 대체분 사용가능시점 판단근거 문서검사 ⑤**표본추출 건에 대해 관찰을 통해 가동여부 확인** |

이 절차들을 시뮬레이터의 민감도 결과와 연결하면:

| 사례 | ±1개월 오차 시 Δ당기순이익 | ±3개월 | ±6개월 | 자산총계 대비 비중 |
|---|---|---|---|---|
| SK하이닉스 FY2023(연결) | 약 642억원 | 약 1,927억원 | 약 3,854억원 | 4.92% |
| SK하이닉스 FY2023(별도) | 약 577억원 | 약 1,731억원 | 약 3,462억원 | 4.78% |
| 삼성전자 FY2024(연결, 근사) | 약 5,229억원 | 약 1조5,686억원 | 약 3조1,371억원 | 7.82% |

**분석**: "당기 대체분 표본추출 - 근거문서상 사용개시시점과 감가상각개시점이 일치하는지
검토"라는 절차는, 이 표에서 보듯 단 **1개월**의 판단 오차만으로도 수백억~수천억원의
당기순이익이 왜곡될 수 있기 때문에 필요합니다. 즉 이 KAM에서 "왜 표본추출로 근거문서
날짜를 대조하는 절차가 핵심감사사항 대응절차로 선택되었는가"는 임의적인 것이 아니라,
개월 단위의 판단 오차가 만들어내는 손익 왜곡의 크기(위 표)로 설명됩니다.

또한 삼성전자 원문에만 있고 SK하이닉스 원문에는 없는 절차가 하나 있습니다 — **"표본추출된
건에 대해 관찰을 통해 가동여부 확인"**, 즉 문서 검토를 넘어선 실물 현장 관찰입니다. 이는
(가설적 해석) 삼성전자는 KAM에 정확한 대상금액을 공시하지 않고 재무제표 주석의 취득액으로
근사해야 할 만큼 대상 모집단이 넓고 불명확한 반면, SK하이닉스는 KAM 원문에 정확한 금액을
직접 특정(4,940,500백만원)하고 있어 이미 모집단이 좁게 특정된 상태라는 차이에서 비롯되었을
가능성이 있습니다 — 모집단이 넓을수록 문서검사만으로는 부족하다고 판단해 물리적 관찰이라는
보강 절차를 추가했다는 해석입니다. 다만 이는 두 회사 원문을 비교한 데서 나온 추정이며,
감사인의 실제 판단 근거를 확인한 것은 아닙니다.

### 원문을 확보하지 못한 사례 (한계 명시)

SK하이닉스 FY2025(연결·별도)와 삼성전자 FY2025(연결)는 `kam_facts.csv`에 KAM 대상금액이
있고 이 KAM이 disclosed된 사실 자체는 사업보고서 요약표(핵심감사사항 목록)로 확인됩니다.
그러나 "핵심감사사항이 감사에서 다루어진 방법" 원문 단락은 확보한 `raw_filings/` 자료
안에서 찾지 못했습니다 — 두 사례 모두 전년도(2023/2024)와 회사·주제가 동일하므로 절차
구성이 비슷할 가능성은 있지만, 확인되지 않은 추정을 확인된 사실처럼 표에 올리지는
않았습니다. 이 상태를 그대로 `data/audit_procedures.csv`의
`procedure_text_confirmed=FALSE` 행에 남겨두었습니다.

## 타 CIP 보유 기업 확장 시도: LG디스플레이 사례 (KAM 미해당)

삼성전자·SK하이닉스 외에 CIP(건설중인자산)를 보유한 다른 ICT 기업으로도 이 KAM이
나타나는지 확인하기 위해 LG디스플레이의 연결감사보고서 3개년치(FY2023~FY2025,
2024.03/2025.03/2026.03 제출분)를 검토했습니다.

| 회계연도 | 감사인 | 핵심감사사항(KAM) |
|---|---|---|
| FY2023 (제39기) | 삼정회계법인 | ① 디스플레이 현금창출단위 손상검사, ② 이연법인세자산 실현가능성 평가 |
| FY2024 (제40기) | 삼일회계법인 | ① 현금창출단위 손상평가, ② 이연법인세자산 실현가능성 평가 |
| FY2025 (제41기) | 삼일회계법인 | ① 영업권 배분 현금창출단위 손상검사 |

3개년 모두 "건설중인자산 → 유형자산 대체(가동개시) 시점 판단"은 KAM으로 다뤄지지
않았습니다. 대신 영업권/CGU 손상검사와 이연법인세자산 실현가능성이 반복적으로
선정되고 있습니다.

**해석**: 이 KAM은 CIP를 보유한 모든 기업에서 자동으로 나타나는 게 아니라, *대규모
신규 팹 증설이 진행 중이고 그 판단의 금액적 임팩트가 클 때* 나타나는 것으로 보입니다.
삼성전자·SK하이닉스는 이 기간 동안 평택·용인·이천 등에서 신규 팹을 계속 증설하는
성장 국면인 반면, LG디스플레이는 같은 기간 중국 광저우 법인 매각(주석 30 참조) 등
사업 축소·구조조정 국면에 있어 손상·이연법인세 이슈가 감사인 입장에서 더 유의적인
것으로 판단됩니다. 즉 "CIP 보유"는 필요조건일 뿐, "활발한 신규 자산 증설"이 이 KAM이
뜨기 위한 추가 조건이라는 정황을 보여줍니다.

이에 따라 LG디스플레이에 대한 시뮬레이션 확장은 진행하지 않았으며, 삼성전자·SK하이닉스
분석에 집중하는 것으로 방향을 정리했습니다.

## DART Open API 자동 대사 (`dart_fetcher.py`)

지금까지 이 프로젝트의 모든 숫자(`data/*.csv`)는 사람이 DART에서 PDF 감사보고서를 내려받아
직접 읽고 옮겨 적은 것이었습니다. `dart_fetcher.py`는 그 중 재무제표 계정과목 금액(자산총계,
유형자산)을 [DART Open API](https://opendart.fss.or.kr)의 `fnlttSinglAcntAll` 엔드포인트로
독립적으로 재조회하여, `data/total_assets.csv`의 수기입력값과 자동으로 대사(reconcile)합니다.

```bash
export DART_API_KEY=발급받은키      # PowerShell: $env:DART_API_KEY = "발급받은키"
python dart_fetcher.py
```

API 키는 opendart.fss.or.kr에서 이메일 인증만으로 즉시 무료 발급됩니다. 코드에는 키를
하드코딩하지 않고 환경변수로만 읽도록 했습니다.

**적용 범위와 한계**: DART Open API는 재무제표 "계정과목·금액"은 구조화된 JSON으로
제공하지만, 핵심감사사항(KAM) 본문 텍스트는 자유서식 원문 문서(감사보고서 PDF/HTML)
안에만 존재하고 별도의 구조화 API가 없습니다. 따라서 이 스크립트는 "숫자 검증 자동화"까지만
다루며, `data/audit_procedures.csv`의 KAM 원문 절차 텍스트 추출은 여전히 수동 확인에
의존합니다 — 자동화할 수 있는 부분과 사람이 원문을 읽고 판단해야 하는 부분을 구분한
것 자체가 이 스크립트의 설계 의도입니다.

**실행 확인 참고**: 이 저장소를 작업한 환경에는 실제 Python 인터프리터가 설치되어 있지
않아(Windows Store 실행 별칭만 존재) 이 스크립트를 직접 실행해 결과를 검증하지
못했습니다. Python이 설치된 환경에서 위 명령으로 직접 실행해 확인해 주세요.
